# C Network Controller & Adaptive Traffic Control (Phases 5 & 14)

Part of the **“Explainable, User-Aware ML System for Adaptive Network Traffic Management in Small LANs”** project.

---

> [!IMPORTANT]
> **Linux & Mininet Enforcement Requirement**
> **Actual traffic control requires a Linux environment.**
> The macOS development environment may be used for development, compilation, and dry-run simulation, but **Linux/Mininet is required for actual `tc`-based enforcement**.
> For safety, the default operating mode is **`DRY_RUN = true`**. The user must explicitly pass `--enforce` to mutate Linux kernel traffic shaping parameters.

---

## 1. Purpose

The **C Network Controller** serves as the central operational hub of the LAN. It performs two critical functions:
1. **Telemetry Hub (Phase 5)**: Ingests real-time streaming telemetry from distributed C monitoring agents across the Mininet LAN.
2. **Adaptive Traffic Controller (Phase 14)**: Translates high-level QoS policy decisions (`HIGH`, `MEDIUM`, `NORMAL`, `LOW`) generated by Phase 13 into actual Linux `tc` (Traffic Control) hierarchical queue disciplines, classes, and filters.

---

## 2. Architecture

```text
                 NETWORK SIDE (C)
                        │
        ┌───────────────┴───────────────┐
        ▼                               ▼
 [ Telemetry Hub ]             [ Adaptive Controller ]
 (network_controller)           (adaptive_controller)
        │                               ▲
        │ TCP Socket Telemetry           │ Policy Decisions
        ▼                               │
 data/monitoring/               data/policy/qos_decisions.csv
 network_metrics.csv                     ▲
        │                               │
        └────────── ML PIPELINE ────────┘
           K-Means + GRU + Policy Engine
```

### Internal Component Design
* `adaptive_controller.py`: CLI entrypoint for batch decision parsing and control invocation.
* `control_interface.py`: High-level command dispatcher supporting `APPLY`, `REMOVE`, `UPDATE`, `STATUS`, and `RESET` / `ROLLBACK`.
* `flow_mapper.py`: 5-tuple parsing from Phase 13 `flow_id` and interface/device resolution.
* `tc_manager.py`: Linux `tc` HTB qdisc, class, and u32 filter construction with strict input allowlisting to prevent shell injection.
* `control_logger.py`: Thread-safe CSV auditing logging into `data/control/control_actions.csv` and `data/control/control_state.csv`.
* `rollback.py`: Tracks active project handles and executes targeted teardown of project-created qdiscs without touching unrelated system networking.

---

## 3. Linux Requirements

Actual enforcement requires:
* Linux Kernel 4.x or higher with `sch_htb` and `cls_u32` kernel modules loaded.
* `iproute2` package containing `tc` and `ip`.
* Root / `sudo` privileges to modify kernel queuing disciplines.

---

## 4. Mininet Requirements

* Mininet 2.3+ installed on Linux (or Mininet VM).
* Open vSwitch (OVS) kernel switch.
* Central switch `s1` with client interfaces `s1-eth1` through `s1-eth5` connecting hosts `h1` through `h5`.

---

## 5. Linux `tc` (Traffic Control) Dependency

Traffic shaping is implemented via the Linux Hierarchical Token Bucket (HTB) queuing discipline:
* **Root Qdisc**: `tc qdisc add dev <iface> root handle 1: htb default 30`
* **Root Class**: `tc class add dev <iface> parent 1: classid 1:1 htb rate 100mbit ceil 100mbit`
* **Priority Classes**:
  * `1:10` (HIGH): `rate 100mbit ceil 100mbit prio 1`
  * `1:20` (MEDIUM): `rate 60mbit ceil 80mbit prio 2`
  * `1:30` (NORMAL): `rate 30mbit ceil 50mbit prio 3` (default)
  * `1:40` (LOW): `rate 10mbit ceil 20mbit prio 4`
* **Flow Classification**:
  * `tc filter add dev <iface> protocol ip parent 1:0 prio 1 handle <id> u32 match ip src <ip>/32 match ip dport <port> 0xffff flowid 1:<class>`

---

## 6. Configuration

Configurable parameters are centralized in `control_config.h`:
* Bandwidth rates: `RATE_HIGH` ("100mbit"), `RATE_MEDIUM` ("60mbit"), `RATE_NORMAL` ("30mbit"), `RATE_LOW` ("10mbit").
* Priority levels: `PRIO_LEVEL_LOW` (0), `PRIO_LEVEL_NORMAL` (1), `PRIO_LEVEL_MEDIUM` (2), `PRIO_LEVEL_HIGH` (3).
* Allowlisted interfaces: `s1-eth1` .. `s1-eth5`, `h1-eth0` .. `h5-eth0`, `lo`.
* Default dry run: `DEFAULT_DRY_RUN = 1`.

---

## 7. DRY_RUN Mode

To prevent accidental disruption of host networking:
* `DRY_RUN = true` is enforced by default.
* In dry-run mode, all parameters are validated, flow 5-tuples parsed, and exact `tc` commands synthesized.
* Results are recorded in `data/control/control_actions.csv` with status `DRY_RUN`.

---

## 8. Applying Rules

### Build Binaries
```bash
make -C network/controller clean all
```

### Run in Dry-Run Mode (Simulation)
```bash
./network/controller/adaptive_controller --apply-csv data/policy/qos_decisions.csv --dry-run
```

### Run with Actual Linux Enforcement
```bash
sudo ./network/controller/adaptive_controller --apply-csv data/policy/qos_decisions.csv --enforce
```

---

## 9. Rollback & Reset

To cleanly revert all changes without affecting unrelated traffic:
```bash
./network/controller/adaptive_controller --rollback
```
Rollback removes only handle `1:` qdiscs and filters created on managed interfaces (`s1-eth1` to `s1-eth5`).

## 10. Control Logs & State

1. **`data/control/control_actions.csv`**:
   Complete audit trail of every control attempt with fields:
   `timestamp,device_id,flow_id,src_ip,dst_ip,src_port,dst_port,protocol,traffic_class,predicted_congestion_class,final_priority,action,target_class,interface,dry_run,status,rule_identifier,error_message`
   Possible statuses: `SUCCESS`, `FAILED`, `SKIPPED`, `DRY_RUN`.

2. **`data/control/control_state.csv`**:
   Active registry of current rules applied on network interfaces.

3. **`data/control/control_summary.json`**:
   Aggregated metrics on applied, updated, skipped, and dry-run actions.

## 11. Troubleshooting

* **Issue: "Interface not in allowlist"**
  * Verify interface name matches allowlisted topology interfaces in `control_config.h` (`s1-eth1` .. `s1-eth5`).
* **Issue: "tc: command not found"**
  * Ensure `iproute2` is installed on your Linux distribution (`sudo apt-get install iproute2`).
* **Issue: Execution fails with status FAILED**
  * Check `data/control/control_actions.csv` error_message column for detailed diagnostics.

---

## 12. Limitations

* **No Payload Inspection**: The controller relies strictly on network metadata (5-tuple, protocol, port) without inspecting packet contents.
* **Platform Specificity**: `tc` kernel hooks are native to Linux. Non-Linux platforms execute via the built-in simulation layer.
* **Stateless Flow Resets**: If the Mininet topology is stopped and restarted (`mn -c`), root qdiscs must be re-initialized.
