# Phase 7: Feature Extraction Module

Explainable, User-Aware ML System for Adaptive Network Traffic Management in Small LANs

---

## 1. Overview

The **Feature Extraction Module (Phase 7)** is a Python-based processing pipeline that transforms raw network flow telemetry generated by the C Network Controller and Phase 6 Ingestion into structured, explainable, and machine-learning-ready numerical features.

```
C Monitoring Agent (Phase 4)
             ↓
     TCP Socket Stream
             ↓
C Network Controller (Phase 5)
             ↓
  Data Ingestion (Phase 6)
             ↓
data/monitoring/network_metrics.csv
             ↓
==========================================
   PHASE 7: FEATURE EXTRACTION PIPELINE
==========================================
             ↓
data/features/network_features.csv
             ↓
Future ML Modules (Phase 8: User Profiling, Phase 9: Congestion Prediction)
```

---

## 2. Input and Output Datasets

### Input Dataset: `data/monitoring/network_metrics.csv`
Contains 11 validated telemetry fields:
- `timestamp`: Measurement timestamp (`YYYY-MM-DD HH:MM:SS`)
- `device_id`: Device identifier (e.g. `h1`, `h2`)
- `src_ip`, `dst_ip`: Source and destination IPv4 addresses
- `src_port`, `dst_port`: Source and destination TCP/UDP port numbers
- `protocol`: Transport protocol (`TCP` or `UDP`)
- `throughput`: Instantaneous flow throughput in Mbps
- `rtt`: Round-trip time in milliseconds (or `N/A`)
- `packet_loss`: Packet loss percentage (or `N/A`)
- `active_connections`: Current active connection count

### Output Dataset: `data/features/network_features.csv`
Contains structured, explainable features preserving physical units without premature black-box normalization.

## 3. Feature Catalog

### Flow-Level Features
| Feature Name | Data Type | Physical Unit | Description / Formula |
|---|---|---|---|
| `flow_id` | `string` | ID | `{device_id}_{src_ip}:{src_port}->{dst_ip}:{dst_port}_{protocol}` |
| `throughput_mbps` | `float` | Mbps | Instantaneous flow throughput rate |
| `traffic_volume_mbps` | `float` | Mbps | Derived throughput volume rate indicator |
| `rtt_ms` | `float` | ms | Round-trip latency (preserved as `NaN` if UDP/missing) |
| `packet_loss_percent` | `float` | % | Flow packet loss percentage |
| `active_connections` | `integer` | Count | Active socket connections |
| `protocol_numeric` | `integer` | Flag | `TCP = 1`, `UDP = 0` |

### Time & Diurnal Features
| Feature Name | Data Type | Valid Range | Description |
|---|---|---|---|
| `hour` | `integer` | `0–23` | Hour of the measurement timestamp (24h) |
| `minute` | `integer` | `0–59` | Minute of the measurement timestamp |
| `day_of_week` | `integer` | `0–6` | Day index (`0` = Monday, `6` = Sunday) |
| `is_weekend` | `integer` | `{0, 1}` | Binary flag: `1` if Saturday/Sunday |
| `time_of_day` | `string` | Categorical | `night` (0–5), `morning` (6–11), `afternoon` (12–17), `evening` (18–23) |

### Device-Level Aggregations (Grouped by `device_id`)
| Feature Name | Data Type | Unit | Description |
|---|---|---|---|
| `mean_throughput_mbps` | `float` | Mbps | Average observed throughput for the device |
| `max_throughput_mbps` | `float` | Mbps | Peak observed throughput for the device |
| `min_throughput_mbps` | `float` | Mbps | Minimum observed throughput for the device |
| `throughput_std` | `float` | Mbps | Standard deviation of throughput (`0.0` if <= 1 sample) |
| `mean_rtt_ms` | `float` | ms | Average RTT across device's TCP flows |
| `max_rtt_ms` | `float` | ms | Peak RTT across device's TCP flows |
| `rtt_std` | `float` | ms | Standard deviation of RTT |
| `mean_packet_loss_percent` | `float` | % | Mean packet loss percentage |
| `max_packet_loss_percent` | `float` | % | Maximum packet loss percentage |
| `packet_loss_std` | `float` | % | Standard deviation of packet loss |
| `mean_active_connections` | `float` | Count | Average concurrent connections on device |
| `total_flow_count` | `integer` | Count | Total telemetry flow records for the device |
| `tcp_flow_count` | `integer` | Count | Count of TCP telemetry records |
| `udp_flow_count` | `integer` | Count | Count of UDP telemetry records |

### Traffic Mix Ratios
| Feature Name | Formula | Range | Description |
|---|---|---|---|
| `tcp_flow_ratio` | `tcp_flow_count / total_flow_count` | `0.0–1.0` | Proportion of TCP flows |
| `udp_flow_ratio` | `udp_flow_count / total_flow_count` | `0.0–1.0` | Proportion of UDP flows |

### Rolling Window Features (Configurable, Default 5 Minutes)
| Feature Name | Window | Description |
|---|---|---|
| `rolling_mean_throughput_5m` | 300s | Rolling average throughput per device |
| `rolling_mean_rtt_5m` | 300s | Rolling average RTT per device |
| `rolling_mean_packet_loss_5m` | 300s | Rolling average packet loss per device |

## 4. Missing-Value Handling Strategy

1. **No Data Fabrication**: We strictly avoid imputing `0` for missing RTT or packet loss. UDP flows inherently lack TCP handshake/acknowledgment RTT measurements; replacing these with `0` would falsely imply zero-latency perfection.
2. **Preservation of `NaN`**: Missing values are stored as empty/NaN in the feature CSV and safely excluded (`skipna=True`) during statistical aggregation.
3. **Variability Zero-Handling**: Standard deviation for single-sample devices safely defaults to `0.0` rather than generating `NaN`.

## 5. Usage & CLI

### Run Feature Extraction
```bash
python3 ml/features/feature_extractor.py \
    --input data/monitoring/network_metrics.csv \
    --output data/features/network_features.csv \
    --sample
```

### Command-Line Arguments
- `--input <path>`: Path to input CSV (default: `data/monitoring/network_metrics.csv`).
- `--output <path>`: Path to output CSV (default: `data/features/network_features.csv`).
- `--window <seconds>`: Rolling window duration in seconds (default: `300`).
- `--sample`: Print top feature rows to stdout.
- `--help`: Display CLI options.

## 7. Downstream Compatibility & Scope Note
- **Phase 8 Compatibility**: Preserves `device_id`, timestamps, and all aggregation statistics needed for clustering and user behavior profiling.
